# v0.5.0 — 大文件增量、并行发布与可解释的诊断

发布日期：2026-11-09
对比基线：`v0.4.0`（2026-11-09）

**安装**：[crates.io](https://crates.io/crates/tauri-delta-updater/0.5.0) ·
[docs.rs](https://docs.rs/tauri-delta-updater/0.5.0) ·
[npm](https://www.npmjs.com/package/tauri-plugin-delta-updater/v/0.5.0)

## 升级注意

- **没有破坏性 API 变更**。新增字段都加在 `#[non_exhaustive]` 结构体上，
  新增类型为纯增量；按原有方式接入的宿主无需改代码。
- **TDXB1 只有 0.5.0 起的客户端能应用**。发布端默认不生成它；
  使用 `--large-file-delta` 前必须确认所有客户端都已升级。该开关与
  `--legacy-patch`（面向只认 `BSDIFF40` 的旧客户端）互斥，混用会直接报错。
- `cargo delta init` 新写入的依赖是 `"0.5"`；已有项目的配置不会被改写。

## 新增

- **超大单文件的增量**：新增 TDXB1 分块差分。单文件超过 bsdiff 的内存上限
  （约 240 MB）时，可以改为按内容分块 + 哈希索引生成补丁，内存与文件总大小
  基本无关。真实 17 MB 二进制（0.5% 散点改动 + 8 KB 插入）实测：
  bsdiff 859 B，TDXB1 17 KB，仍只有全量的 0.1%。
  发布端开启方式：`cargo delta release ... --large-file-delta`。
- **发布流水线更快**：多个历史基线并行生成补丁，内存按预估工作集加权
  （默认预算 4 GiB，单任务超预算时独占运行）。新增
  `--jobs` / `--patch-memory-budget-mb` 与
  `TDX_PATCH_JOBS` / `TDX_PATCH_MEMORY_BUDGET_MB`；
  清单与报告顺序与串行版本一致，不会产生额外 diff。
- **诊断能直接回答“上次为什么失败”**：`diagnose()` 新增 `last_attempt`
  （结果分类、耗时、目标版本、稳定错误码），不再需要解析日志或事件流。
- **UI 可以本地化配置警告**：`Diagnosis.warning_keys` 给出稳定语义键
  （工作目录不可写、明文 HTTP、跨用户锁降级等），`warnings()` 保留原文案。
- **跨用户锁可见**：`Diagnosis.machine_lock_active` 明确表示
  `lock_scope: "install_dir"` 是否真正生效；降级时附带警告键。
- **多跳链错误可结构化展示**：`DeltaError::chain_context()` 返回
  `{ hop, total, from, to }`，可以直接显示“第 2/5 跳失败”。
- **一条命令生成密钥**：`cargo delta init --generate-key myapp.key --apply`
  生成密钥对、写入配置；Unix 下私钥权限 `0600`，输出只包含路径。
- **发布后验证**：`cargo delta doctor <url> --pubkey <key> --expect-version 0.5.0`
  在线上版本不符时直接失败。

## 修复

- 多个基线并行生成整包补丁时，临时归档使用唯一文件名，不再互相覆盖。
- `checkCompat()` 的进度回调在一次 `downloadAndInstall` 中只发一次
  `Started` / `Finished`；增量回退全量时不再出现第二个下载会话。
- 清单新增 `patches[].algorithm`：客户端遇到不认识的容器格式会跳过该补丁
  （回退全量），而不是下载后应用失败。

## 验证边界

- macOS Gatekeeper/公证、Windows UAC/单实例、Linux 提权路径仍未在本仓库
  真机验证；CI 只做静态与合成脚本断言。
- TDXB1 已用合成数据与 17 MB 真实二进制验证，**未在真实多 GB 安装包上跑过**；
  首次启用前请在自己的产物上对比补丁体积与耗时。
- 并行生成用 3 个基线验证；几十个基线叠加低内存 CI 的极端场景未实测。
- `authenticode_policy: "permissive"` 与 `lock_scope: "install_dir"` 仍只有
  单元/集成测试，未在真实离线证书链或双用户账户环境下验证。
