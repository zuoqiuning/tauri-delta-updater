# v0.5.1 — 全量安装可确认、替换启动更可靠

发布日期：2026-11-10
对比基线：`v0.5.0`（2026-11-09）

**安装**：[crates.io](https://crates.io/crates/tauri-delta-updater/0.5.1) ·
[docs.rs](https://docs.rs/tauri-delta-updater/0.5.1) ·
[npm](https://www.npmjs.com/package/tauri-plugin-delta-updater/v/0.5.1)

## 升级注意

- **没有破坏性 API 变更**。新增字段都加在 `#[non_exhaustive]` 结构体上，
  接入代码无需改动。
- **全量安装失败不再冻结增量更新**。全量失败写入独立的
  `full_update_failures.txt`，只通过 `diagnose().full_failures` 展示；
  `should_abort()` 只读取增量失败计数。用户取消安装器、拒绝提权不会再让
  增量通道进入安全模式。
- **Windows 替换脚本只在安装目录不可写时才请求管理员权限**。per-user 安装
  （`%LocalAppData%`）不再每次更新都弹 UAC，与 Unix 的
  `[ ! -w "$TARGET_DIR" ]` 行为对齐。
- 工作目录会新增两个状态文件：`tdx_full_pending.json`（全量待确认）与
  `tdx_update_in_progress.json`（替换进行中）。无需手动处理。

## 新增

- **全量安装的启动确认**：启动安装器前记录目标版本，下次启动对比当前版本。
  达到目标即确认成功并清零全量失败计数；超过 1 小时仍未达标则计入一次
  全量失败。安装器本身启动失败也计入。
- **`tdx-testkit` 首次发布**：把仓库内部的 mock 更新服务（含 `Range` 续传）、
  minisign 助手与签名清单构造器开放给接入方，写集成测试不必重造夹具。
  只依赖签名/JSON 库，不进入生产构建。
- **`DeltaUpdater::diagnostic_bundle()`**：诊断快照 + 脚本日志尾部 200 行 +
  原始事件流打包成一份 JSON，报障只需一个文件。
- **“上次更新没走完”可观测**：`diagnose().update_in_progress` 返回
  目标版本与启动时间；替换脚本成功或回滚完成时清除。
- **`diagnose().full_failures`**：连续全量安装未生效次数，与增量安全模式隔离。

## 修复

- **替换后新版本没启动（`startup_not_started`）**：Windows 脚本通过
  `explorer` 代理拉起应用时，代理可能静默不启动。现在启动后会确认进程真的
  出现，没有就退回直接启动；超时日志记录启动方式、PID 与退出码，不再只有
  一个没有证据的回滚原因。
- **全量失败污染增量安全模式**：取消安装器/拒绝提权曾计入共享失败计数，
  三次就会冻结增量 6 小时；现在全量失败独立计数，不再影响增量。
- **per-user 安装的无谓 UAC**：Windows 脚本不再无条件 `RunAs`。
- **`simulate_update` 示例**改在 16 MB 栈线程中运行，修复 Windows debug 构建
  校验 8 MB 级文件时的栈溢出。

## 验证边界

- 本次新增的 Windows 启动确认/兜底逻辑由真实 PowerShell 执行测试覆盖，
  **尚未在真机桌面会话完整跑过主动替换**；发布前请按 `docs/DEVICE_TESTS.md`
  在目标机器上跑一次 Passive / Quiet。
- macOS `.app` 的 Gatekeeper/公证、Linux 提权路径仍未在本仓库真机验证；
  CI 只做静态与合成脚本断言。
- 全量安装的 1 小时宽限期与失败计数未在不同磁盘/Defender 配置下长时间实测。

本版本发布后不可覆盖；后续版本须经项目所有者明确授权。
