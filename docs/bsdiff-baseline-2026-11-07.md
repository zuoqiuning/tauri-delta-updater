# bsdiff + zstd 基线采样（2026-11-07）

> 目的：用**现有后端**回答“Zucchini 是否值得投入”的一半问题。
> 本文件只记录真实产物，不包含 Zucchini 数据（当前环境没有 clang，无法构建 `zucchini-sys`）。

## 环境

- 平台：Windows x86_64
- Rust：stable（release 构建）
- 后端：`qbsdiff` + zstd（`simulate_update` 的真实路径）
- 命令：

```bash
cargo run --release --example simulate_update -- \
  test_run/old.exe test_run/new.exe target/delta-sim
```

## 样本 1：相邻构建的 27 MB PE

| 项目 | 值 |
|---|---|
| 旧文件 | `test_run/old.exe`，27,298,304 字节 |

| 补丁占比 | **0.01%** |
| 补丁 SHA-256 | `d7888a2f8a9baaba22980b4c00b0a3f109aa246676cfeebdc4ebd0c4d7935f1f` |
| 产物 SHA-256 | `451cf51d508abc8a26cd43d65611a5f1c4673e74c3ded4b0d3ee01ec723fd0f8` |

### 解读

- 这是“相邻构建、只有很小差异”的形态（版本号/资源/少量代码），bsdiff+zstd 已经把补丁压到
  全量的 0.01%。对于这一类发布，Zucchini 没有可证明的空间。
- 因此 **Zucchini 的优先级应放在“单模块重编译 / 完整重编译 / 时间戳大面积变化”场景**，
  而不是相邻小改版本。
- 该样本不能代表“仅时间戳变化”或“工具链切换”；这些需要真实历史 artifact。

## 采样矩阵与预期

| 场景 | 当前状态 | 预期补丁占比 | 说明 |
|---|---|---|---|
| 相邻构建（版本/资源小改） | **已测：0.01%** | < 1% | 现有后端已接近理论上限，Zucchini 无空间 |
| 仅版本字符串变化 | 待采集 | < 1% | 与相邻构建接近；预计不需要 Zucchini |
| 仅构建时间戳/元数据变化 | 待采集 | 1–10%（假设） | 若明显高于 10%，Zucchini 的归一化有明确价值 |
| 一个模块重编译 | 待采集 | 1–10%（假设） | 中等变更，最值得对比 |
| 完整重编译 / 工具链升级 | 待采集 | 30–100%（假设） | Zucchini 的极限场景；若 bsdiff 已接近全量，才值得投入 |

上面三行“预期”是待验证假设，不是结论；采样后必须用实测值替换。

## 数据缺口与扩充路径

仓库里目前只有这一对可用的真实主程序；`mock_release/` 里是安装包，不能作为补丁基底。
历史产物会随着 `generate --archive-dir` 的发布流程自然积累：
每次发布把主程序归档为下一版基线，`old_binaries/` 达到 5 对后按本文件的方法重新采样。
要完成决策，至少还需要：

1. 仅版本字符串变化（同一二进制改版本资源）；
2. 仅构建时间戳/元数据变化；
3. 一个模块重编译；
4. 完整重编译或工具链升级。

采集方式：从 CI 历史 artifact 或本地 `old_binaries/` 取 5–10 对主程序，逐对运行
`simulate_update`，把上表复制成多行。Zucchini 的对照数据用
`tools/zucchini-ab` 在有 clang 的机器上补齐。

## 当前结论

- **不把 Zucchini 集成进 `core::diff`**：没有数据支持，且当前环境无法构建。
- **相邻构建场景不需要 Zucchini**：现有 bsdiff+zstd 已接近理论上限。
- 下一步先补真实样本矩阵，再决定是否投入 Zucchini。
